# js_of_ocaml

js_of_ocaml (jsoo) is a compiler that translates OCaml bytecode into JavaScript.
It is a **whole-program** compiler — it parses the entire `.byte`, builds one SSA
IR for the whole program, and runs global optimisation passes over it — so it
holds the whole program in memory and RSS / live-heap grow with the input, unlike
the per-module compiler benchmarks (`ocamlc_self_compile`) where the live set
stays bounded.

## Ladder

The ladder scales the **size of the input bytecode**. jsoo's cost tracks program
*structure*, not raw bytes (a synthetic file of thousands of tiny closures is
pathological), so the rung inputs are built from **real code**: the 20 JSOO
classic benchmark sources wrapped in unique modules and replicated R times, then
compiled with the runtime-under-test's own `ocamlc` (magic-matched). The `.ml` is
runtime-independent, the `.byte` per-runtime; both are generated by `jsoo.build.sh`
and gitignored. Measured on OCaml 5.5.0, Ryzen 9 9950X (`fingerprint.sh`
`v=0x400`; olly gc%/pause from `perf_grp1|re-25|md-2`):

| rung | replicas | bytecode | wall | RSS | gc% | max pause |
| --- | --- | --- | --- | --- | --- | --- |
| `_small` | 30 | 5.6 MB | 5.1s | 0.5 GB | 32.8% | 6.8 ms |
| `_default` | 80 | 14 MB | 15.8s | 1.7 GB | 31.4% | 32.8 ms |
| `_large` | 200 | 36 MB | 49.5s | 7.8 GB | 33.4% | 129 ms |

RSS grows ~linearly with the input and the promotion fraction climbs slightly
(0.28 → 0.33) — a promotion-heavy footprint ladder. Like ocamlformat, jsoo holds
a **constant ~33 % gc%** across every size (uniformly minor-GC and IR-allocation
heavy), while the **max pause grows to ~129 ms at `_large`** (p99.9 ~30 ms) as the
major collector scans a multi-GB pointer-dense SSA IR — a dual signal: steady
minor-GC throughput plus growing major-GC scan latency. A huge band is deferred.
(olly's `promoted_pct` reads ~8× low — the minor-allocation-counter units bug; the
`v=0x400` fractions are correct.)

## Legacy

Kept for reference, not run by default (`RUNNING_TAG=legacy`):

- `jsoo` — the original fixed-input bench, compiling the runtime-under-test's own
  `ocamlc.byte` (~3.5 MB) to JavaScript.

## Notes

Two vendoring pins matter, both handled by `scripts/setup-monorepo.sh`:

- jsoo is vendored from a `master` commit (the `[5;7]` OCaml bound), because the
  6.2.0 release hard-rejects OCaml 5.5+ with an assertion.
- cmdliner is pinned to 2.1.0 (not 1.3.0), because jsoo uses
  `Cmdliner.Arg.Completion`, which arrived in cmdliner 2.0.

The wrapper writes a sibling findlib config with absolute paths pointed at by
`OCAMLFIND_CONF`, so jsoo resolves runtime stubs regardless of the working
directory (the opam `findlib.conf` uses relative paths and would fail with
`No_such_package(stdlib)`).
