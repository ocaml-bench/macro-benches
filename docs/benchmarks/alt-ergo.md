# alt-ergo

Alt-Ergo is an SMT solver aimed at program-verification problems. This directory builds one
`alt-ergo` binary and runs it on three different input files, so the three programs share a
binary but differ in frontend and in the shape of the solving work.

`alt-ergo.build.sh` does a `dune build` of `Main_text.exe` with the runtime-under-test and
copies the binary out (it is a standalone copy, not a wrapper). Before building, it also
regenerates the `fill` input (see below). The run flags and input selection for each of the
three programs come from the running-ng suite config, not from the build script.

## What it runs

| program | input | frontend | notes |
| --- | --- | --- | --- |
| `alt_ergo_fill` | `fill_x100.why` | native `.why` | 100 independent goals, generated from `fill.why` |
| `alt_ergo_yyll` | `yyll.why` | native `.why` | larger single native input |
| `alt_ergo_unsat_smt2` | `unsat.smt2` | Dolmen `.smt2` | run with `--timelimit 15` |

`fill_x100.why` is generated by the build script, not checked in as a hand-written file.
`fill.why` has a single goal (`fill_assert_39`); the script replicates that goal block 100
times with renamed identifiers (`fill_assert_1` .. `fill_assert_100`) so alt-ergo solves
each one independently. Work scales roughly linearly, about 0.14s per goal, so 100 goals
comes out around 14s. The file is regenerated only when `fill.why` changes.

`yyll` and `fill` go through the native `.why` parser; `unsat_smt2` goes through the Dolmen
`.smt2` frontend instead. `unsat_smt2` is the only one run with a time limit
(`--timelimit 15`), which arms a `SIGVTALRM` timer that may fire at the end of a long solve.

## Knob-A ladder (single-solve problem size)

`alt_ergo_fill` above scales by *repetition* (100 independent copies of one goal —
Knob B: the peak working set is one goal's, wall is linear in the count). The
`alt_ergo_chain_{small,default,large}` rungs scale the working set of a **single**
solve instead. `alt-ergo.build.sh` generates `alt_ergo_chain_<rung>.why`: one goal
asserting `a(0) = 0` and `a(i) = a(i-1) + 1` for `i` in `1..N`, proving `a(N) = N`.
alt-ergo must build an N-term congruence/arithmetic structure in one solve, so the
live heap grows with N — this is the same chained array-cell reasoning `fill.why`
exercises (Frama-C/WP VCs), parameterised. Solving is super-linear (~N^2.2 in both
wall and live heap). Measured on OCaml 5.5.0, Ryzen 9 9950X (`fingerprint.sh`
`v=0x400`; olly gc%/pause from `perf_grp1|re-25|md-2`):

| rung | N | wall | gc% | RSS | top_heap | minor GC | major GC | p99.9 | max pause |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `_small` | 4000 | 4.2s | 13.6% | 0.59 GB | 76M w | 3699 | 16 | 3.0 ms | 3.9 ms |
| `_default` | 7000 | 14.1s | 17.8% | 1.88 GB | 244M w | 10979 | 20 | 9.0 ms | 11.0 ms |
| `_large` | 10500 | 37.8s | 25.7% | 4.88 GB | 638M w | 24610 | 24 | 22.1 ms | 27.4 ms |

Each rung reaches a strictly bigger live-heap regime: `top_heap` 76 → 638M words (8.4×,
tracking RSS 0.6 → 4.9 GB), minor collections 3.7k → 25k. Unlike the other ladders,
**gc% rises** with N (13.6 → 25.7%) and **pauses grow steeply** (p99.9 3 → 22 ms, max
28 ms): the solve builds one large, mostly-live structure (promotion fraction only
~0.09-0.14, major cycles just 16 → 24), so the cost is scanning an ever-bigger live
heap on each major slice — a heap-scan-bound ladder, the counterpoint to cpdf
(GC-share falls as C work dominates) and liq_video_frames (pacer-bound, tiny pauses).
A huge band is deferred (N≈14000 would be ~min-scale at ~9 GB).

## What it stresses

All three are compute-bound in the SMT theory backend (DPLL(T), congruence closure, integer
arithmetic, bitvectors). That is where most of the time goes. On the runtime side, the
things that stand out:

- Weak hashsets for term hash-consing. Alt-Ergo's `hconsing.ml` uses `Weak.Make` to
  deduplicate structurally identical subterms, so every theory term constructor goes
  through a weak hashset. In the OCaml runtime `Weak.Make` is ephemeron-backed, so this
  also drives the ephemeron-cleaning path. This is one of the suite's two hot weak-array
  workloads (Frama-C's CIL hash-consing is the other).
- `Hashtbl` at scale, separately from the weak set, for solver state, CDCL clause
  databases, and theory caches.
- Signal handler registration. `signals_profiling.ml` installs handlers for `SIGINT`,
  `SIGVTALRM` and `SIGPROF`. Only `unsat_smt2` actually arms the timer (via `--timelimit`);
  on `fill` and `yyll` the handlers are installed but never fire. No alt-ergo benchmark
  exercises high-frequency signal delivery.

## Reading the results

Rough baseline numbers:

- `alt_ergo_fill`: wall around 14s (100 goals at roughly 0.14s each).
- `alt_ergo_yyll`: wall around 19s, GC overhead around 6%, on the order of 7500 minor / 18
  major collections.
- `alt_ergo_unsat_smt2`: wall around 15s, GC overhead around 7%, on the order of 12400
  minor / 42 major collections.

If all three move together, suspect the theory backends or the weak-hashset (term
construction) path. If only `unsat_smt2` moves, look at the Dolmen frontend or the timeout
signal interaction. If `fill` and `yyll` move but `unsat_smt2` does not, look at the native
`.why` frontend. If all three move but nothing else in the suite does, that points at
`Weak.Make` / weak-pointer cleaning.

## Notes

All three alt-ergo programs crash at run under ocaml-mmtk (SIGSEGV, because MMTk is a moving
collector), so they are excluded from the MMTk minheap and GC sweeps. They run fine on the
stock and PR-branch runtimes.
